三、锁定在设计里的决策（实现按此执行）

决策定稿
回复无边框文档流范式（对齐官方/主流 harness）：助手输出直接铺页面背景，不套气泡/容器——表格、代码占满宽度；用户消息保留气泡区分角色；工具行/思考行/回合头各自保留浅底色条做视觉分层
回合头常显回合内 ≥1 个工具或思考 → 必有回合头；纯文本回合不出现（就是普通一条回复）
折叠语义折叠只藏「过程」（思考 + 工具行），正文永远显示；历史回合默认折叠，当前回合默认展开
头部内容运行中：正在工作… + 转圈 + 实时动词计数；完成：已工作 X 分 X 秒 + 「编辑 N · 查阅 M」中文动词计数
思考行🧠 思考 · 持续了 N 秒，点击展开灰色思考内容（二级折叠）
工具行中文动词 + 文件末段 + 行数增减（+N -M，从 Edit 输入的 old/new 算）+ 查阅聚合「· N 文件」+ 运行计时 + 失败标（⚠ 执行失败 · 已重试恢复）
动作类型五分法终端⌘（命令截断显示）· 写入（新文件 +N）· 编辑（+N -M）· 读取（单文件）· 查阅（搜索/多文件聚合）；尾部灰勾 = 完成
思考在时间线内思考行与工具行、叙述文本穿插在真实时间线位置（不是独立前置块）——「⏳ 思考 · 持续了几秒」可展开内容
叙述文本内联agent 在工具之间的中间叙述（如"E41 宿主 Node 是 24.18.0…"）按原序渲染在流程中——这是「过程完整」的关键，历史路径也必须保序
聚合规则连续同类聚合：「查阅 · N 搜索 / N 文件」「终端 · N 个命令 ▾」（聚合行可展开逐条）；编辑/写入不聚合（逐文件可见）
工具行二级展开每个工具行可点开：终端 = 完整命令 + 输出；编辑 = old/new 红绿 diff；写入 = 新文件内容；查阅 = 逐文件/逐搜索。输入不再 200 字符截断——全量保存，展开时按需渲染
块级按钮复制（正文 Markdown）/ 下载（.md）/ 全文（放大查看）——位于块尾右下，整回合一组
数据结构回合 = 有序 parts 列表（thinking/text/tool 按引擎原序）；流式与历史两条路径产出同构结构——顺序完整性的根治
