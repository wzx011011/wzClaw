wzxClaw v3 「大脑网络」架构总览

个人 AI 远程控制系统。引擎标准化为 ZCode app-server（官方无头运行时），手机 / 桌面都只是它的前端；节点间经自托管 NAS relay 会合，数据不过第三方云。

组件职责

NAS relayNode.js · ws · relay/zcode/server.js
  • sid/hash 房间模型：房间 id 由 HMAC-SHA256(pass_hash, "zcode-relay-sid:" + device_mid) 确定性派生——companion 重启 / 重连不换码，手机配对一次长期有效。
  • 配对协议：device_register_init → auth_init → auth_challenge → auth_response(HMAC proof) → auth_ack / pair_status_ack；配对后 relay 只做盲转发。
  • 角色配额：每房间 1 个 device（companion）+ 最多 3 个 probe（手机）；多手机对 companion 透明。
  • 半开接管：持有 proof 的一方可驱逐按 last-pong 判定为陈旧的旧连接；未认证者不可驱逐。
  • 注册密钥：REGISTRATION_SECRET + timingSafeEqual 防公网注册 DoS。
  • 限额：帧 ≤1 MiB；maxSockets 32 / maxRooms 16 / maxProbes 3；控制帧 120/10s；流式数据独立配额；房间 TTL 60s；ping 30s。
Companion（CLI 常驻节点）Node.js · relay/zcode/companion.js
  • Windows 常驻进程，注册为 device 角色；桥接 relay data 载荷 ↔ 本地 zcode app-server stdio NDJSON（缓冲上限 32 MiB）。
  • 自动应答 session/requestRuntimePreferences；其余反向请求（权限等）转发到手机。
  • 反向请求超时档位：权限 / 确认类 120s、白名单外 15s；超时自动拒绝（-32022）——失败方向偏向「多等 / 多确认」。
  • 凭据纪律：模型 token 从 ~/.zcode/v2/config.json 读取、仅注入子进程 env，不落盘 / 不进日志 / 不过 relay。
  • 自启动走 Windows 计划任务 wzxClawZcodeCompanion（勿挂在代理任务托管里，会被回收）。
Companion App（桌面版）Electron 41 · electron-builder · companion_app/
  • 完整形态：状态灯、配对二维码、设置（relay 地址 / cwd / 自启）、日志；宠物形态：透明置顶、颜色随状态（绿=已配对 / 黄=等待 / 灰=离线 / 红=桥错误）。托盘常驻。
  • 内嵌而非包装：cclient/ 是 companion / server 源码的verbatim 副本，由主进程直接驱动，无需系统 Node。
  • 与 CLI companion 共享 ~/.wzxclaw/zcode-companion/ 凭据（同配对免重扫）；单实例锁。
  • 首跑 ZCode 健康门（只读检测 + 短命 session/list 探针）后才连线。
手机 App（wzxClaw）Flutter 3 · Provider · sqflite · wzxClaw_android/
  • 目标栈lib/zcode/：ZcodeChatStore（每会话状态容器 / epoch 失效 / 增量权威刷新 afterMessageId）、ZcodeDesktopRegistry（多桌面注册表，一桌面一配对一 Store）、relay 客户端（指数退避重连 + 抖动）、权限 / AskUser 组件、SQLite 快开缓存、模型自愈。
  • 翻译壳lib/services/：WsEvents 形状旧协议栈，zcode_protocol_translate.dart 把引擎帧翻译成旧形状供现有 UI 使用；退役条件 = 聊天页换接线到直连栈。
  • 页面：home / landing / settings / 扫码 / 文件浏览 / 目标面板；部件：permission_bar、ask_user_bar、connection_status_bar、tool_card 等。

协议与数据流

ZCode Protocol v1 要点（唯一事实源：relay/zcode/APP-SERVER.md）

  • stdio NDJSON，类 JSON-RPC 但无 jsonrpc 字段；服务端反向请求用字符串 id（如 "server-1"）；无 initialize 握手。
  • 核心方法：session/{create,resume,list,send,stop,messages,events,subscribe,setModel,setMode,…}；session/send 参数名是 content；session/subscribe 需 deliveryKind（web-remote-replayable = 可回放事件流）。
  • 错误码：-32004 会话非活跃（运行时单归属——桌面运行中的会话对 companion 不可读 / 不可订阅，这是设计不是 bug）；-32022 客户端反向请求超时。
  • 分页契约：{limit} = 最新 N 条升序；{afterMessageId, limit} = 后缀最新 N 条；收敛信号 = 条数 < limit。
  • 协议为非官方逆向：改协议代码前先跑探针（probe-methods.js / probe-models.js，~30 个探针钉 schema），锁定已验证 CLI 版本。

端到端数据流（生产 v2 配对流）

  1. 手机扫码 / 粘贴配对 URL（sid + hash）→ 以 probe 角色连 WSS，按房间做 HMAC 挑战认证。
  2. companion（device 角色、确定性 sid）已在房间 → pair_status: matched。
  3. 手机在 relay {type:'data', payload} 信封内发 ZCode Protocol v1 帧；relay 盲转发。
  4. companion 把帧灌进本地 app-server stdio；应答 / 事件流回传；反向请求（如权限）转发到手机弹权限卡片；工具执行发生在节点所在机器。
  5. 模型调用经桌面侧凭据（编码计划 key）直连模型端点。

设计原则（2026-09-15 审查定稿，摘要）

  1. 协议字段以实测为准：形状来自 APP-SERVER.md 实测记录，不许直觉猜字段；新接口先跑探针。
  2. 一步到位，不留「先用假的」：硬编码占位、乐观回显不回填、吞错误——宁可显式报「暂不支持」。
  3. 失败模式偏向多等 / 多确认，而非静默拒绝 / 丢失。
  4. 静默丢弃 = 缺陷：不可识别帧必须有观测手段。
  5. 语义映射写明词典：枚举不对齐时显式定义映射表。
  6. 安全约定自我一致：密钥不进参数 / 日志 / 输出，全链路遵守；凭据文件 0600。
  7. 回归测试钉住契约：修 bug 先加能复现的测试再修。

部署与运维

  • NAS（群晖 DS923+）：relay 跑 Docker 容器 wzxclaw-zcode-relay（relay/zcode/Dockerfile，deploy-nas-zcode.sh 幂等部署，绑定 127.0.0.1:18884）；公网入口 wss://zcode.5945.top/ws 经 nginx 子域名反代（Upgrade 头、剥 Origin、/health）。
  • Windows 节点：计划任务 wzxClawZcodeCompanion（VBS 隐藏窗口）或 Electron Companion App（NSIS / 便携版，npm run dist）。
  • APK 发布纪律：产物放 NAS /volume1/share/zcode/wzxClaw-android-release-vX.Y.Z.apk；每包 patch +1 且 versionCode 单调递增；被取消过的构建必须 flutter clean 重建，上架前 apksigner verify + zip 完整性检查 + 哈希比对。
  • 配对凭据纪律：sid / hash / token / QR 是持有者凭据，不进日志 / git / 聊天输出。
