wzxClaw Current Architecture

当前真实架构：共享 Web UI + 本地 IPC 模式 + NAS Agent Server + 可注册 Hands

1. 一句话总览

@wzxclaw/brain 纯 TypeScript Agent 核心，不依赖 Electron。
  • AgentLoop / streaming tool execution
  • LLMGateway / OpenAI-compatible / Anthropic
  • Context / permission / observability interfaces
agent-server NAS 上的远程 Brain 入口。
  • WebSocket chat/client protocol
  • Hand registry and tool routing
  • SQLite session persistence
Hands 真正执行工具的进程。
  • Desktop HandBridge
  • NAS docker-hand
  • capabilities + isReadOnly metadata
web-ui / clients 同一套 React UI 运行在桌面和手机。
  • Electron: IpcDataSource
  • Capacitor/mobile: WebSocketSource
  • Browser: WebSocketSource
当前主链路已经不是旧的“手机 ↔ relay ↔ 桌面”模式。主聊天链路是客户端直接连接 NAS agent-server；桌面同时可以作为 Hand 注册给 NAS，让远程 Brain 调用本地工具。

3. Monorepo 模块边界

packages/brain
  • 纯逻辑核心，零 Electron 依赖。
  • 通过 IStreamProvider、IToolExecutor、ISessionStore、IPermissionManager 注入外部能力。
  • AgentConfig.targetHandId 贯穿到 IToolExecutionContext，用于远程工具按 Hand 定向。
packages/agent-server
  • 使用 @wzxclaw/brain 创建远程 AgentLoop。
  • ClientHandler 按 WebSocket 连接隔离运行状态和 stop 信号。
  • HandAwareToolExecutor 把工具调用转给健康 Hand。
  • SessionStoreSqlite 持久化远程会话。
packages/hand
  • Hand 协议、状态、工具定义和本地执行器。
  • 可作为 NAS docker-hand 运行，也被桌面 HandBridge 复用。
  • 注册时上报 capabilities 和 isReadOnly。
packages/web-ui
  • 共享 React SPA。
  • 通过 DataSource 接口屏蔽 IPC 和 WebSocket 差异。
  • 包含 chat、sessions、IDE layout、Monaco、xterm、mobile shell。
wzxClaw_desktop
  • Electron main/preload/renderer 外壳。
  • Main 进程提供本地 IPC 能力、桌面本地 Agent、工具、MCP、工作区和会话。
  • HandBridge 可连接 NAS，把桌面注册为远程 Hand。
mobile
  • Capacitor Android 壳。
  • 构建 packages/web-ui 后同步到 Android WebView。
  • 通过 WSS 连接 NAS agent-server。

5. Agent Server 内部结构

HTTP + WebSocket server
  • /health 返回服务、会话和 Hand 状态。
  • /admin/hands 需要 token。
  • WebSocket 统一承载 client 和 hand 协议。
ClientHandler + SessionService
  • 处理 chat:send、chat:stop、session:list/load/create/delete/rename。
  • SessionService 是会话元数据、运行状态和 AgentConfig 默认值合成的边界。
  • 支持 session:config:get/update，会话级默认值优先于客户端全局选择。
  • 每个连接有独立 ConnectionState，避免多客户端串扰。
  • 流式事件回传给客户端。
HandAwareToolExecutor
  • 按 targetHandId 或工具名选择健康 Hand。
  • 发送 hand:execute，等待 hand:result。
  • 默认阻止非只读远程工具。
远程写工具的默认策略是拒绝：除非设置 WZXCLAW_ALLOW_REMOTE_WRITE_TOOLS=1，否则 FileWrite、FileEdit、Bash 等非 readonly 工具不会通过远程 Hand 执行。

6. Desktop Electron 三进程

Main Process
  • BrowserWindow、Menu、启动生命周期。
  • IPC handlers：agent、session、workspace、file、terminal、browser、settings、host、mcp。
  • 本地 Brain adapter、ToolRegistry、PermissionManager、SessionStore、MCP client。
  • HandBridge 连接 NAS agent-server。
Preload
  • contextBridge.exposeInMainWorld('wzxclaw', api)。
  • 把主进程 IPC 映射为稳定的 window.wzxclaw.* API。
  • 包含 web-ui 需要的 fs、terminal、preview 兼容别名。
Renderer
  • 加载共享 packages/web-ui bundle。
  • Electron 下自动选择 IpcDataSource。
  • React 19 + Zustand 5 + Monaco + xterm。

7. Hand 协议和工具执行

事件方向说明
hand:registerHand → agent-server注册 Hand ID、名称、capabilities、工具 definitions 和 readonly 标记。
hand:heartbeatHand → agent-server保持健康状态；服务端返回 hand:heartbeat_ack。
hand:executeagent-server → Hand远程工具调用，携带 callId、toolName、input、workingDirectory。
hand:resultHand → agent-server返回工具输出和 isError。
hand:reloadagent-server → Hand管理端触发 Hand 重新加载能力。
Desktop HandBridge 和 NAS docker-hand 都走同一套 @wzxclaw/hand 协议。区别在于 Desktop Hand 能访问用户本机工作区和 UI/IPC 能力，docker-hand 主要访问 NAS Compose 挂载的 /data。

8. 数据和配置存储

Desktop local storage
  • %APPDATA%/wzxclaw/settings.json：桌面设置。
  • %APPDATA%/wzxclaw/sessions/{projectHash}/*.jsonl：桌面本地会话。
  • ~/.wzxclaw/MEMORY.md 和 ~/.wzxclaw/memory/{projectHash}：记忆。
  • {workspace}/.wzxclaw/index：本地语义索引。
NAS server storage
  • /data/sessions.db：远程会话 SQLite。
  • /data/.wzxclaw/api-keys.json：API key 配置，优先级高于旧 env key。
  • ./data:/data：Compose 数据卷。
  • AUTH_TOKEN：HTTP/WSS 统一认证 token。

9. 旧 Relay 的位置

relay/ 现在不是主聊天架构的中心
  • relay/ 仍保留为独立 WebSocket relay 服务代码，面向旧的手机 ↔ 桌面房间模型。
  • 桌面端已移除 legacy relay runtime；旧 relay IPC 仅保留兼容壳并返回断开状态。
  • 当前已验证的真实端到端链路使用 agent-server 的公网入口 agent.5945.top。
  • 新文档和测试应优先描述 WebSocketSource → agent-server → Brain → Hand。
