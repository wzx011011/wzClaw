wzxClaw 架构对比：现状（翻译壳）vs 目标（UI 直连）

依据：AGENTS.md 双栈现状、connection_manager.dart / chat_store.dart 实读、relay/zcode/APP-SERVER.md 实测（2026-09-17 更正版）
区别的本质三句话： ① 线上协议——生产链路已经是 app-server 帧（手机发 zcodeRequest、收 session/event）；WsEvents 形状只活在手机端翻译层之上； ② 翻译层——生产链路的翻译点在手机端一层（zcode_protocol_translate：引擎事件 → WsEvents 形状喂 ChatStore）；休眠支线上另有一个节点侧翻译进程（brain-adapter，已随 token relay 下线）。方向：删掉手机端翻译层，UI 直接消费引擎事件； ③ relay——现在是两个 relay（token 房间那个已下线）；方向是只留 v2 relay 哑管道。

一、现状：一条生产链路（带手机端翻译壳）

现用 UI 就跑在这条链路上。引擎与线上帧早已全部是 app-server；不彻底的只有"事件消费"一段——引擎事件回来要先翻成 WsEvents 形状才能进 ChatStore。

手机 UI（home_page，做好即不变） 正在使用 消息渲染、工具卡片、权限条——全部挂在这个页面上
WsEvents 形状消息（stream:agent:*，仅存在于手机端内部）
翻译壳（services/） 现网唯一翻译点 · 退役目标 ChatStore 数据容器 ＋ 翻译层 zcode_protocol_translate（connection_manager.dart:280 translateNotification）
把引擎事件翻成 WsEvents 形状 → ChatStore → 页面
app-server 帧（zcodeRequest 发 / session/event 收）
v2 relay 生产 wss://zcode.5945.top/ws · sid/hash 房间 · 注册密钥 · 半开接管
data 载荷哑转发
companion 生产 Windows 常驻节点 · 配对 QR · 哑转发（不翻译）
stdio NDJSON
zcode app-server（唯一引擎） 会话存储共享 · 运行时单归属（-32004）
旁路：wzxClaw_desktop（旧 Electron IDE，UI+runtime 一体）与该链路互不可见运行时；M3 计划内嵌适配器双挂同一引擎。

二、目标方向：删翻译壳，UI 直连

即「不翻译」——页面数据源改挂 ZcodeChatStore，手机端内部不再有协议翻译；端到端从 UI 到引擎只有一种协议形状。

手机 UI（同一个，不变） home_page 的数据源改接：聊天/会话/权限全部读 ZcodeChatStore
引擎事件原样消费（无翻译）
ZcodeChatStore 直连栈（lib/zcode） 每会话状态容器 / 同步层 / 反向请求自答 / SQLite 缓存
翻译壳（ChatStore ＋ zcode_protocol_translate） 删除
app-server 帧 —— 唯一协议，端到端不变
v2 relay（唯一会合点） 哑管道：房间 / 配对 / 认证 · 可选补一个离线暂存小特性
data 哑转发
companion（唯一节点形态） 可移植 NAS Docker（哑转发，成本很低）
stdio NDJSON
zcode app-server（唯一引擎） M3：桌面 IDE 内嵌适配器双挂同一引擎 → 手机/桌面同视实时

维度现状（翻译壳）目标（UI 直连）

翻译层手机端一层（zcode_protocol_translate：引擎事件 → WsEvents 形状）；休眠支线另有 brain-adapter（已下线）无——UI 直接消费引擎事件

节点形态companion（哑转发·生产）＋ brain-adapter（翻译节点·休眠）一种：companion（可移植 NAS）
UI ↔ 数据容器UI 不变，页面当前接在 ChatStore（翻译壳）上；ZcodeChatStore 建成未挂接UI 不变，页面数据源改接 ZcodeChatStore；删翻译壳
离线队列token relay 有过 24h 暂存（随下线消失）无——节点离线即不可达；靠 SQLite 缓存+回连权威刷新补历史。可在 relay 补小特性

认知成本高：线上明明是 app-server，代码里却要懂两种形状；文档需解释谁是活的（本次多次困惑的根源）低：一种形状，一张图讲完

四、两图之间的差距（迁移清单）

  1. 聊天页换接线（唯一大块）：UI 不变，把页面数据源从 ChatStore（翻译壳）改挂 ZcodeChatStore（直连栈），真机跑稳即完成切换。
  2. 退役翻译壳（其余已先行完成：brain-adapter / remote_control_page / 夹具 / Dockerfile.brain 已于 2026-09-17 删除）：换接线跑稳后删 lib/services/ WsEvents 协议栈与 zcode_protocol_translate；文档同步。
  3. 节点可移植（可选）：companion 移植 NAS Docker——哑转发所以成本很低。
  4. 离线队列决策：实际用下来若"节点离线时指令丢失"确实痛，在 v2 relay 加按房间暂存，不复活旧协议。
