01当前运行架构

实线为请求方向 · 响应原路返回

三个部署位置，四个职责边界relay 只路由；companion 桥接并处理扩展；模型调用和工具执行归节点本机。
  1. Android：现用 UI → ZcodeChatStore → ZcodeRelayClient；ConnectionManager 拥有 client 并 attach 给 store，扩展服务经 ConnectionManager 调用同一 client。SQLite 仅缓存已确认消息。
  2. NAS relay：WSS data 信封进入房间；重写请求 ID，定向返回结果；通知广播，反向请求只交一个手机客户端。
  3. companion：GUI 内嵌于 Electron main；CLI 直接运行 Node 入口。原生请求写入 app-server 的 stdin；x/* 在 companion 本机处理。
  4. app-server 子进程：管理会话、回合、事件、模型调用与本机工具，stdout 返回 NDJSON；同一会话只有一个运行进程。
  5. 反向权限交互：app-server → companion → relay → 手机权限队列 → 原路回传所选 option.response。
  6. 联网与引擎：设备先注册 relay，runtime gate 独立预检并热注入引擎；引擎失败不等于设备离线。

INVARIANT 01

会话只有一个运行归属

app-server 持有会话运行状态。其他运行进程正在使用的会话可能返回 -32004；手机端按会话分别保存状态，不跨进程接管回合。

INVARIANT 02

在线状态与引擎健康独立

GUI 先让 companion 上线，再异步预检引擎。runtime descriptor 热注入，预检失败不拆 relay 连接；引擎重启通过 generation 作废旧请求与订阅。

INVARIANT 03

权威数据与缓存各司其职

会话消息以 session/messages 回填；模型目录取 resume / create 的 available 投影。SQLite 和导入快照不能冒充引擎可用性；read 的 current-only 投影不是目录源。
